# 接口说明

## 通用约定

- 本地后端为 `http://127.0.0.1:8080`，前端开发服务器代理 `/api` 和 `/uploads`。
- JSON 字段使用下划线形式，如 `vehicle_id`、`planned_start`。
- 日期为 `YYYY-MM-DD`，时间为不带时区的本地 ISO 日期时间，如 `2026-10-28T15:00:00`。前后端及数据库按同一运行时区理解业务时间。
- 金额最多两位小数，服务端使用 `BigDecimal` 和 `DECIMAL`。
- 登录使用 HttpOnly 会话 Cookie。浏览器写请求携带 `X-Requested-With: XMLHttpRequest`，并检查允许的 Origin。
- 成功直接返回对象或集合。业务错误返回 400 和 `message`；未登录返回 401；接口权限不足返回 403。
- 当前列表由 `/bootstrap` 提供，筛选和分页在前端完成，不宣称实现了服务端分页。

## 认证

- `POST /api/auth/login`：传入 `username`、`password`、`portal`（`ADMIN` 或 `CUSTOMER`），返回无密码字段的当前用户；旧客户端可省略 portal。
- `POST /api/auth/register`：仅开放客户注册，字段 `username`、`password`、`name`、`phone`、`identity_no`、`license_no`、`license_expiry`。拒绝管理角色注册及重复证件绑定。
- `GET /api/auth/me`：查询当前账号。
- `POST /api/auth/logout`：退出。
- `POST /api/auth/password`：传入 `old_password`、`new_password`，修改后当前会话退出。

## 公共数据

- `GET /api/bootstrap`：车辆、客户、订单、流水、门店、价格、调度、工单、保养提醒和系统基本参数。
- `GET /api/dashboard`：管理端当月工作台；管理员与业务人员拥有相同访问权限。
- `POST /api/uploads`：表单字段 `file`，只接收 5MB 以内可解码的 PNG、JPEG，返回图片访问地址。
- `GET /uploads/{name}`：登录后读取图片。

## 车辆与客户

- `POST /api/vehicles`：新增车辆，默认可用。
- `PUT /api/vehicles/{id}`：编辑基础档案，不允许直接改变状态或所属门店。
- `POST /api/vehicles/{id}/toggle`：管理员停用、启用车辆，停用前检查关联业务。
- `POST /api/customers`：登记客户。
- `PUT /api/customers/{id}`：修改客户和限制租赁状态。

车辆字段包括 `plate`、`brand`、`model`、`category`、`color`、`seats`、`purchase_date`、`license_no`、`mileage`、`branch_id`、`pricing_id`、`image`、`next_service_date`、`next_service_mileage`。

客户字段包括 `name`、`identity_no`、`phone`、`license_no`、`license_expiry`、`category`、`restricted`、`notes`。

## 计费及订单

- `POST /api/pricing/quote`：传入 `vehicle_id`、`billing_mode`、`planned_start`、`planned_end`、`expected_mileage`；返回 `rent`、`deposit`、`days`、`mileage`、`formula`。试算不等于预留车辆。
- `POST /api/orders`：除报价字段外，还需 `customer_id`、`pickup_branch`、`return_branch`。
- `PUT /api/orders/{id}`：修改未收款待取车订单，不变更客户及车辆，重新报价。
- `POST /api/orders/{id}/collect`：`request_id`、`kind`、`amount`；类型为 `DEPOSIT` 或 `RENT`。
- `POST /api/orders/{id}/pickup`：`start_mileage`、`condition`。
- `POST /api/orders/{id}/return`：`end_mileage`、`return_branch`、`extra_fee`、`discount`、`fee_notes`、`condition`、`damage`。
- `POST /api/orders/{id}/settle`：`request_id`，按待结差额生成收款或退款记录。
- `POST /api/orders/{id}/cancel`：`request_id`，退还净已收款并取消。

收款、取消、结算必须有独立业务请求号。重复操作被拒绝，不额外产生流水。实际交车、还车及结算时间由后端生成。

计费枚举为 `DAILY`、`MILEAGE`、`MONTHLY`。订单状态为 `RESERVED`、`ACTIVE`、`RETURNED`、`COMPLETED`、`CANCELLED`。

## 调度与维修

- `POST /api/dispatch`：`vehicle_id`、`to_branch`、`assignee`、`planned_start`、`planned_end`、`notes`。
- `POST /api/dispatch/{id}/start`：开始。
- `POST /api/dispatch/{id}/complete`：到达并更新门店。
- `POST /api/dispatch/{id}/cancel`：取消待执行任务。
- `POST /api/maintenance`：`vehicle_id`、`type`、`project`、`assignee`、`cost`。
- `POST /api/maintenance/{id}/start`：开始，传空对象。
- `POST /api/maintenance/{id}/complete`：`cost`、`next_date`、`next_mileage`。
- `POST /api/maintenance/{id}/cancel`：取消待处理工单，传空对象。

任务状态为 `PENDING`、`IN_PROGRESS`、`COMPLETED`、`CANCELLED`。工单类型为 `REPAIR` 或 `SERVICE`。

## 报表与系统管理

以下接口均要求管理角色 ADMIN（含业务人员账号）。客户访问这些接口返回 403。

- `GET /api/reports?from=YYYY-MM-DD&to=YYYY-MM-DD`：统计区间最多 367 天。
- `GET /api/system`：账号、系统参数、最近 300 条操作日志。
- `POST /api/system/users`、`PUT /api/system/users/{id}`：账号管理；编辑时密码留空表示不修改。
- `POST /api/system/branches`、`PUT /api/system/branches/{id}`：门店管理。
- `PUT /api/system/pricing/{id}`：修改规则，不追溯变更已有订单快照。
- `PUT /api/system/settings`：`reminder_days`、`reminder_km`；忽略公司名称修改。
- `GET /api/system/backup`：下载数据库和图片 ZIP 快照。
- `POST /api/system/restore`：表单字段 `file` 和值为 `RESTORE` 的 `confirmation`。只导入可信 ZIP，恢复完成全部会话失效。

## 客户端

- `GET /api/portal/bootstrap`：仅本人客户档案、订单与收退款；车辆隐藏行驶证和内部养护字段，不返回后台调度、工单、提醒与系统参数。
- `PUT /api/portal/profile`：仅更新本人 `name`、`phone`、`license_no`、`license_expiry`；不能改角色、限制租赁、会员等级、身份证号或客户归属。
- `POST /api/portal/quote`：复用服务端报价。
- `POST /api/portal/orders`：客户编号由会话决定，取车店由车辆决定；接收车辆、租期、计费方式、预计里程、还车店。
- `POST /api/portal/orders/{id}/cancel`：仅本人待取车且净收款为零的预约；有收款则引导管理员退款处理。
- 角色仅 `ADMIN`、`CUSTOMER`；`account_type` 为 `ADMIN`、`STAFF`、`CUSTOMER`。管理端创建客户账号须关联唯一的已有 `customer_id`。
- 报表 `usage[].revenue` 为查询区间按完成日期统计的实际租金，与报表总收入求和一致，不含押金。

## 模块边界

车辆状态不接受任意字符串更新。租金计算与订单共用后端计费服务，报表只读取业务数据。订单、调度、维修修改同一车辆前锁定车辆记录，避免并发绕过校验。
