# 团队协作与完成标准

## 项目目录与主责

- `frontend/src/views/`：前端业务页面，八个模块分别独立。
- `frontend/src/components/`：公共组件，UI 与前端共同确认规范。
- `backend/src/main/java/com/yixing/`：按 auth、vehicle、customer、order、pricing、dispatch、maintenance、report、system 等包拆分后端。
- `database/`：数据库结构脚本，由后端统一修改并同步给测试。
- `tests/`：浏览器验收脚本、测试依赖和报告。
- `docs/`：需求、界面、接口、运行及协作说明。

## 四个岗位

1. **UI：**负责页面与交互规范、设计评审、视觉验收；成果放入 `docs/`，必要时配合调整样式。
2. **前端：**负责 Vue 页面、公共组件、真实接口接入、页面异常处理。
3. **后端：**负责数据库、接口、计费、事务、权限、状态流转与业务单元测试。
4. **测试：**负责用例、虚构数据、接口和浏览器验收、缺陷复验及测试报告。

## Git 提交流程

项目使用 GitHub 私有仓库 `AprilHRH/yixing-rental`。仓库管理员先邀请其他成员获得访问权限，四人再克隆同一项目；本次已将当前完整源码作为初始版本提交，之后按任务分支协作。

从最新 `main` 创建具体任务分支，例如 `feat/order-return`、`fix/vehicle-status`、`test/order-pricing`。不要长期使用彼此隔离的前端、后端分支。

修改后先自测，再执行 `git add`、`git commit`、`git push`，最后在托管平台发起 PR。由另一成员检查后合并。数据库文件、上传目录、依赖和本地工具已在 `.gitignore` 中排除。

## 功能完成标准

每个功能建立任务记录，状态按“待开发 → 开发中 → 待联调 → 待测试 → 已完成”推进。

- 后端完成：真实数据库保存正确、参数和权限校验通过、文档和脚本同步、业务测试通过。
- 前端完成：使用真实接口、页面交互及失败反馈正确、刷新后数据仍正确、构建通过。
- 功能完成：真实接口联调通过、测试验收通过、代码评审并合并。
- 测试记录注明代码版本或提交号，不以“已经 push”代替验收。

## 当前模块边界

车辆状态由订单、调度、维修驱动，不提供任意改状态接口。价格规则由管理员维护，订单保存快照。押金流水不作为收入。客户都是业务档案，不是登录账号。
