# 本轮功能与界面改造报告

完成日期：2026-10-29。

## 运行入口

- 管理端及统一登录：<http://127.0.0.1:5173/#/login>。
- 客户端：<http://127.0.0.1:5173/#/portal>，需先选择客户身份注册或使用管理员开通的客户账号。
- 管理员账号 admin 与业务人员账号 staff 沿用原密码，均从“管理员登录”进入。仅权限合并，业务人员身份通过 account_type 保留。

## 逐项完成

- 权限仅分 ADMIN、CUSTOMER。原 STAFF 账号启动时迁移为 ADMIN，account_type=STAFF，原账号和密码不变；前后端同时执行角色边界。
- 登录页增加管理员与客户两个入口；公开注册只能创建客户账号，并事务性创建客户档案。拒绝越权注册、重复账号与冒领已有身份证档案。
- 管理端可新增管理员、业务人员及关联已有客户档案的客户登录账号，提供启停和重置密码。没有档案的客户可先建档，或自主注册。
- 客户端提供车型筛选、车辆图文、报价、预约、本人订单与流水、取消未收款预约、个人资料更新。收款、交还车、退款及结算由管理端办理。
- 删除公司名称编辑；后端系统参数更新也不再写入公司名称。
- 报表车辆使用保留一张图文排行，删除重复明细表。支持出租时长、出租次数、租金收入切换并降序排列。收入来自查询区间内已完成订单实际租金，与总收入合计一致。
- 每日经营明细日期倒序，不改变经营趋势图的时间正序。
- 保养提醒无记录时整个区域与顶部提醒入口隐藏。创建按钮与新增工单同样明显，已创建待处理工单可直接开始，开始后提醒消失，工单本身仍保留在记录中。
- 维修、调度、报表、客户历史订单、工作台最近订单、车辆选择器统一补充对应图片；保留原有订单、车辆卡片与详情图片。
- 调度运力及模块概览数字加大、加重并使用数字字体与区分色。
- 租金计算按天只选日期范围，按里程只输入公里数，包月只选本年度起租月份；删除独立计费规则表。旁边展示当前车辆、单价与简明计算依据。
- 包月继续以 30 天为一个计费月，不暗改原订单价格口径；选择月份后从该月 1 日开始计算 30 天，并明确显示起止日。
- 订单页删除业务待办下拉筛选，保留订单状态；工作台跳转的待办范围以可清除提示呈现，原深链接不失效。
- 对现有 18 款车型图片的示意车牌增加展示层遮挡，业务车牌文字仍正常展示。原始图片与来源说明未删除。
- 全站切换清透蓝白、深海军蓝文字与焦橙操作，侧栏加入现有汽车摄影背景。局部玻璃只用于顶栏、侧栏底部，不模糊业务内容；改善按钮对比度、表格宽度和数字字体。

## 修改文件

### 前端

- `frontend/src/views/Login.vue`、`frontend/src/views/CustomerPortal.vue`：双入口登录、客户注册及三个客户端页面。
- `frontend/src/views/Settings.vue`：团队与客户账号、关联档案、权限说明、参数精简。
- `frontend/src/views/Reports.vue`：车辆图文排行及三指标切换、每日明细倒序。
- `frontend/src/views/Pricing.vue`：按方式切换输入、当年月份、车辆价格与试算。
- `frontend/src/views/Maintenance.vue`、`frontend/src/views/Dispatch.vue`：提醒操作、车辆图片及突出数字。
- `frontend/src/views/Orders.vue`、`frontend/src/views/Customers.vue`、`frontend/src/views/Dashboard.vue`：删除重复筛选、图文补齐与表格可读性。
- `frontend/src/components/VehicleIdentity.vue`、`frontend/src/components/VehicleThumbnail.vue`、`frontend/src/components/FormDialog.vue`：共用车辆图文、车牌遮挡和选择器。
- `frontend/src/vehiclePlateShields.js`：18 张参考素材的车牌遮挡坐标。
- `frontend/src/App.vue`、`frontend/src/main.js`、`frontend/src/store.js`：客户端路由守卫、独立菜单与数据初始化。
- `frontend/src/refinement.css`：本轮视觉与响应式规则。

### 后端与数据库

- `auth/AccountService.java`、`auth/AccountUpgrade.java`、`auth/AuthController.java`、`auth/SessionFilter.java`：注册、旧账号迁移、登录身份和后台边界。
- `customer/PortalController.java`：本人档案、订单、支付记录和预约接口；不信任输入客户编号，禁止操作他人订单。
- `system/SystemService.java`：管理员与客户账号、唯一档案关联、参数及旧备份角色兼容。
- `report/ReportService.java`：车辆实际租金聚合。
- `maintenance/MaintenanceService.java`：开始后的保养提醒排除。
- `data/DemoData.java`：新数据库业务账号使用合并角色。
- `backend/src/main/resources/schema.sql`、`backend/src/main/resources/schema-mysql.sql`、`database/schema-h2.sql`、`database/schema-mysql.sql`：账号类型与客户关联字段。

以上 Java 文件均位于 `backend/src/main/java/com/yixing/` 下。

## 实际验证

- 前端 13 项 Node 测试通过；Vite 生产构建通过。
- 后端 15 项测试通过；包括角色合并、客户注册、越权拒绝、档案唯一关联、本人预约、收款后不能自主取消、提醒开始后消失。
- 53 项隔离 H2 浏览器验收通过，包含原有订单收押金、交车、还车、退款结算闭环及新增客户端完整流程，无浏览器脚本错误。
- 本机 5173 使用构建后的前端与真实持久化数据库实测。车辆两页共 18 辆、订单三页共 30 笔图片均加载，对应关系正确；详情和选择器正常。
- 管理端在 1451/1280/768/390px、客户端在 1440/768/390px 检查，无整页横向溢出；表格内部允许滚动。
- 将升级前数据库副本与升级后 API 的车辆、客户、订单、流水、调度和维修记录逐字段比较，均一致：18 辆车、9 位客户、30 笔订单、30 条流水、1 个调度任务、9 个维修工单。
- 注册、预约与新增账号测试均使用独立内存数据库，不向实际业务数据库写入测试客户或订单。

## 边界与遗留提示

- 无已知阻断本次验收的问题。原有 ECharts 和 Element Plus 大体积分包构建警告仍存在，不影响运行；没有新增依赖。
- MySQL 结构脚本已同步，但本机验收使用 H2，未宣称实测 MySQL。
- 车辆图仍是明确标注的车型参考，上传的实车照片优先；示意车牌遮挡按现有 18 张素材定位，不对未来未知上传图片自动识别车牌。
- 客户有收款的预约需联系管理员退款取消；驾驶证仅做资料与有效期校验，未接入外部实名核验、短信或在线支付服务。
- 当前为本地课程系统，未加入互联网部署所需的反滥用、短信找回或生产运营服务。
